# Models — какая модель для какого агента/команды

Описывает модель для каждого агента и команды.
✅ **Применено** — поле `model:` проставлено во frontmatter всех 9 агентов и 11 команд
(сбалансированный профиль). Этот документ — источник правды для конфигурации.

**Дефолт сессии: Opus** — всё, что помечено `inherit` или без поля, работает на Opus.

## Доступные модели

| Модель | ID | Назначение |
|---|---|---|
| **Opus 4.7** | `claude-opus-4-7` | Глубокое многошаговое рассуждение, высокая цена ошибки, креатив |
| **Sonnet 4.6** | `claude-sonnet-4-6` | Солидное кодирование с понятными правилами, ограниченный объём |
| **Haiku 4.5** | `claude-haiku-4-5-20251001` | Механика: запуск команд, печать, простая запись |

## Профиль: Сбалансированный

Opus — на «думающих» агентов; Sonnet — на кодирование по правилам; Haiku — на механику.

### Агенты

| Агент | Модель | Почему |
|---|---|---|
| `code-architect` | **Opus** | Решения по FSD/слоям распространяются на весь код — ошибка дорогая |
| `code-security-auditor` | **Opus** | Безопасность: цена пропущенной XSS/JWT-дыры максимальная |
| `code-debugger` | **Opus** | Root-cause analysis — здесь окупается сильное рассуждение |
| `code-reviewer` | **Opus** | Ловля тонких багов, критический взгляд, confidence-скоринг |
| `code-frontend-design` | **Opus** | Качество и креатив дизайна — главный бенефициар сильной модели |
| `code-refactorer` | **Sonnet** | Реструктуризация по чётким правилам, поведение не меняется |
| `code-test-writer` | **Sonnet** | Тесты по AAA — механика с пониманием API |
| `code-explorer` | **Sonnet** | Read-only трассировка и синтез, без сложных решений |
| `code-doc-writer` | **Haiku** | JSDoc/SPEC — в основном чтение + краткая запись |

### Команды

Большинство команд — тонкие обёртки: они делегируют сабагенту, и решает модель **этого агента**.
Реально настраивать стоит только команды, работающие inline.

| Команда | Модель | Почему |
|---|---|---|
| `feature` | **Opus** | Оркестрация многих агентов с гейтами в главной сессии |
| `run-app` | **Haiku** | Чистый bash: проверка портов + запуск |
| `dod` | **Haiku** | Печать статичного чеклиста |
| `arch` | **inherit** → `code-architect` (Opus) | Делегирует сабагенту |
| `audit` | **inherit** → `code-security-auditor` (Opus) | Делегирует сабагенту |
| `debug` | **inherit** → `code-debugger` (Opus) | Делегирует сабагенту |
| `review` | **inherit** → `code-reviewer` (Opus) | Делегирует сабагенту |
| `refactor` | **inherit** → `code-refactorer` (Sonnet) | Делегирует сабагенту |
| `test` | **inherit** → `code-test-writer` (Sonnet) | Делегирует сабагенту |
| `doc` | **inherit** → `code-doc-writer` (Haiku) | Делегирует сабагенту |

У делегирующих команд `model: inherit` проставлен явно — лёгкая оркестрация идёт на модели
сессии (Opus), а тяжёлую работу делает сабагент на своей модели из его frontmatter.

## Как изменить модель

Поле `model:` во frontmatter агента или команды:

```yaml
---
name: code-architect
model: opus        # opus | sonnet | haiku | inherit
description: ...
tools: Read, Bash, Glob, Grep
---
```

`inherit` — явно наследовать модель сессии (то же, что отсутствие поля).
Изменения вступают в силу при следующем запуске агента/команды.
